# CouchPilot security model

## Scope and trust

Threats considered: an untrusted LAN advertiser/peer, changed TLS identity, malformed responses, nearby Bluetooth peers, stolen app data, accidental public disclosure, stale asynchronous ownership and excessive queued commands. CouchPilot is a client, with no public command server, WebView, deep links, analytics or cloud account. It does not provide protection against a rooted/compromised phone or a malicious approved TV.

Use a trusted LAN. Production socket resolution rejects loopback, unspecified, multicast and public WAN addresses; private/link-local addresses and globally addressed IPv6 within a connected LAN prefix are allowed. LG validates canonical numeric IPv4/IPv6 URL hosts before scheduling any WebSocket socket setup; hostname DNS answers pass through the same LAN policy. LG explicitly bypasses system proxies so proxy-side DNS cannot evade containment. Socket-local non-VPN Wi-Fi/Ethernet selection never changes process routing or VPN settings. Discovery is untrusted metadata; explicit selection and protocol registration establish the device relationship. Cross-subnet private LANs remain possible. This is containment, not cryptographic discovery authentication.

## Credential and Android surface

LG grants use AES-256-GCM, fresh IV, authenticated versioned envelope and Android Keystore wrapping key. Legacy private preference migration is atomic; no plaintext fallback exists. Failure requires explicit authorization recovery and retains the pin. Xiaomi client RSA private key is non-exportable Android Keystore material. Bluetooth bonding secrets remain Android-owned; app preferences contain only selected endpoint/configuration metadata and grants/pins. All private storage domains are excluded from cloud and device-transfer backup; allowBackup is false.

Only launcher Activity is exported by app source. The connected-device foreground service is private; PendingIntents are explicit and immutable. Debug Compose test/tooling components are absent from release. AndroidX profile receiver requires DUMP. Bluetooth CONNECT is requested on API31+, notifications on API33+; no microphone/location/contact/storage permission. Target36 retains current LAN permission behavior; moving to target37 requires a separate local-network runtime permission review.

## TLS and transport

LG uses a device-specific WSS client, no redirects/downgrade, certificate validity plus TOFU on first registration, then strict full-certificate SHA256 pinning. Hostname verification is replaced only within this LG client by pin continuity; there is no shared global TrustAll manager or debug-only security bypass. An established pin mismatch is terminal. Some LG factory certificates may be shared; initial hostile-LAN impersonation remains **MEDIUM**, protocol constrained. TV approval is user consent, not a cryptographic fingerprint comparison.

Google TV pairing code binds protocol identities; subsequent command TLS is pinned. TCP address-family fallback finishes before TLS and cannot turn a certificate failure into another address attempt. IPv4 failure may fall back to IPv6; family ordering is not trust ordering.

UPnP descriptions require HTTP on dynamically discovered IPs. The manifest's cleartext permission remains for that specific metadata path because Network Security Config cannot express arbitrary LAN subnet/IP ranges. The only HTTP code is bounded, no-credential, same UDP-sender host, no userinfo/redirect, strict UTF-8, DTD/entity rejection, bounded depth/elements/time/bytes. SSAP is WSS and Google is TLS. Global cleartext permission is an accepted **LOW** containment risk requiring review of every new HTTP call site; it is not a blanket permission to transmit credentials.

Samsung uses the compatible legacy insecure RFCOMM service on an explicitly selected existing Android bond. Vendor frames have no application-level authentication; **MEDIUM** nearby-radio risk remains. No BLE scanning or unsolicited new bond is used. HID selects an explicit host, filters callbacks to it, validates reports and releases pressed keys during cancellation. State callbacks are conflated, not an unbounded queue.

## Availability and lifecycle

Google framing is bounded at64KiB with malformed varint/length rejection. Samsung framing is bounded at255 bytes plus1024-byte resynchronization and status validation. LG has at most 32 pending requests, a 64-message receive queue and a bounded description scan.

### LG WebSocket message memory

The LG listener rejects text messages longer than **65,536 UTF-16 code units** (`String.length`) and cancels the connection. This is a character-count check after delivery, not a byte limit or a heap-memory ceiling. OkHttp 4.12.0 assembles fragmented messages and, when compression is negotiated, inflates them before calling `onMessage()`. A large text or binary message can therefore consume memory before CouchPilot can reject it. The receive queue bounds delivered messages only. The retained public WebSocket API has no incoming message-size or streaming-frame limit; upgrading to the reviewed 5.5.0 API alone does not supply one. See the upstream [4.12 reader](https://github.com/square/okhttp/blob/parent-4.12.0/okhttp/src/main/kotlin/okhttp3/internal/ws/WebSocketReader.kt) and [5.5 reader](https://github.com/square/okhttp/blob/parent-5.5.0/okhttp/src/commonJvmAndroid/kotlin/okhttp3/internal/ws/WebSocketReader.kt).

**Accepted documented limitation: MEDIUM availability impact, low expected exposure on a trusted home LAN with a trusted selected TV.** A malicious selected endpoint, or a LAN impersonator during first trust, can send messages after the WSS upgrade and before TV registration approval completes. Once a certificate is pinned, a mismatching peer is rejected during TLS before WebSocket messages are read. Subsequent exploitation requires control of the selected endpoint or possession of the pinned identity's private key; the limitation does not bypass certificate pinning. There is no public listener, and advertisements alone do not establish a connection. No confidentiality or code-execution consequence is established by this review.

A transport replacement or custom framing/decompression layer would need a separate compatibility and security review. Retaining this residual risk permits release preparation within the trusted-LAN/trusted-device scope; it does not eliminate the risk or certify a stable signed release. Distribution, signing/upgrade continuity and other release gates remain separate.

Retries use backoff and explicit terminal security/permission handling. LG wake/reconnect, Samsung initial wake recovery and HID outgoing recovery are bounded; steady-state saved connections can retry with backoff. Per-device bounded queues hold at most8 pending intentions, expire stale pending taps and coalesce pending input switches. Active commands are never automatically replayed. Explicit stop rejects ordinary commands and connection-opening setup callbacks, cancels workers and closes adapters, including passive discovery. Foreground return does not resume an explicitly stopped process lease; Resume or an explicit device-setup action starts a new lease. A fresh process opened by the user may start normally. Only the current Samsung generation can publish state/error/mute or clear its session. Google pairing/command writes and Samsung writes/flushes have four-second deadlines: timeout or cancellation closes the immutable owned native connection and joins its IO worker before returning. This relies on the native socket close contract; a coroutine timer alone is insufficient. Samsung’s four-second operation budget includes command/query writes and the status response; failed or cancelled operations retire the uncorrelated stream. Timed-out physical commands are never replayed. Google long-key release remains cancellation-safe and has the same bounded write deadline. Google power observations carry an adapter-assigned revision that advances on every accepted Start frame, including equal Boolean readings. A per-attempt token and active owner Job reject stale publishers; the single latest snapshot retains ordering without an event queue. Power completion checks that snapshot even if its Main collector is delayed, and consumed revisions prevent an old collector reading from overwriting optimism. Last reported power is retained across disconnect; connection availability is separate. LG Connected is a lifecycle transition hint, not periodic authoritative power telemetry; an equal Connected assignment has no new power-report meaning. TV optimism remains a hint guarded against observed connection transitions. Hardware acknowledgements remain separate from optimistic local power hints.

## Diagnostics and publication

Central diagnostics accept only allowlisted fixed metadata and a bounded100-event in-memory history. Release logcat emits no events; debug uses sanitized metadata, never raw packets/keys/codes/hosts/MACs. User errors use localized categories and visible Snackbar/banner, never raw exceptions. Internal exceptions may describe endpoints but are not exported as telemetry or release logs.

Tracked source and reachable history are scanned for key/token/credential material and personal identifiers before publication. Synthetic documentation addresses, test-only grants and in-memory generated test certificates are not real device credentials. Signing keys, environment files, private PEMs, pairing state and local diagnostic dumps are ignored. Findings must not be hidden by deleting only HEAD: actual historical secrets require stopping publication and history sanitation/rotation.

No physical security tests or new device compatibility claims are implied by automated validation. See FINAL_VALIDATION.md and THIRD_PARTY_NOTICES.md.
