# LG webOS LAN control

## Discovery and identity

The app sends a bounded SSDP `M-SEARCH` to `239.255.255.250:1900` for `urn:lge-com:service:webos-second-screen:1`, following LG's Connect SDK discovery filter. Each response supplies a source IP and usually a UUID. If `LOCATION` points back to that same host, the app reads its UPnP `friendlyName` and `modelName` with a short timeout and safe XML parser. Android permits cleartext HTTP for this local discovery description; the control channel uses WSS. Discovery lasts four seconds, holds a Wi-Fi multicast lock, and closes its socket and lock when stopped. Some webOS firmware or network arrangements may omit this service, so a manual host field remains available.

## Registration and storage

The app connects to `wss://<host>:3001/`, sends `hello` with neutral identity `com.myremote.app` / My Remote, then a `register` message with `pairingType: PROMPT`. Its generic unsigned manifest has `manifestVersion: 1` and all requested rights in `payload.manifest.permissions`. There is no `signed` section, `signatures` array, LG test identity, vendor impersonation, or signed-manifest fallback.

| Permission | Reason |
|---|---|
| `READ_INPUT_DEVICE_LIST` | Query actual external input IDs before switching. |
| `CONTROL_INPUT_TV` | Current TV input-control operations. |
| `CONTROL_DISPLAY` | Display/input compatibility; present in LG Connect SDK's protected control set and current compatible unsigned implementations. |
| `CONTROL_POWER` | Current power-off operation. |

`READ_POWER_STATE` is omitted because hardware power state is not currently queried. `CONTROL_AUDIO` is omitted because product volume/mute routes to the Samsung soundbar. Pointer/keyboard (`CONTROL_MOUSE_AND_KEYBOARD`) and text (`CONTROL_INPUT_TEXT`) are omitted because navigation/text do not currently target the LG; Xiaomi owns navigation. App launch, settings, notification, recording, and LG test permissions are not requested. Future features must justify additions and bump the authorization revision.

The baseline already placed `READ_INPUT_DEVICE_LIST`, `CONTROL_INPUT_TV`, and `CONTROL_POWER` in the correct outer array; it also requested `TEST_OPEN` and `TEST_PROTECTED`. It did **not** contain the legacy signed/test signature structure reported by other clients. This change removes the test rights and adds the related `CONTROL_DISPLAY` compatibility right. Sources do not specify this TV firmware's exact per-endpoint permission check: adding `CONTROL_DISPLAY` is a targeted compatibility hypothesis, not proof that this was the single missing permission. The observed 401 conclusively locates rejection at authorization; it does not reveal the TV's granted permission set.

The TV may show an approval prompt. A `response` with `pairingType: PROMPT` keeps the UI in Pairing; a `registered` message must contain `client-key` before the controller proceeds. The app persists the selected host, device identity, client key, authorization revision, TV certificate SHA-256 pin, and configured wake MACs in app-private preferences. Android backup is disabled. Reconnects send the saved key only when its authorization revision matches the current manifest contract, and verify the saved certificate pin. The first registration trusts the TV's self-signed certificate after validity checking and pins it only after TV approval; it does not have a public CA identity. A changed certificate requires re-pairing. No registration secret is logged.

### Refreshing an insufficient grant

The baseline persisted no authorization revision and could indefinitely reuse an insufficient key after a manifest update. Unversioned or outdated keys are now withheld from registration; the controller reports Authorization needs refresh and does not start an approval prompt at launch. Selecting the same TV or pressing Retry cannot silently bypass that requirement.

**Set up LG TV → Refresh LG authorization** cancels and waits for the existing registration/connection job, clears only the LG client key and grant revision, and reconnects with the unsigned manifest and no `client-key`. This requests a fresh TV approval. Host, name, model, UUID, wake MACs, and the existing certificate pin remain intact. On `registered`, the new key and current revision are saved. Repeated refreshes remain available if the TV still denies control. This retires the local key; it does not claim to delete registrations stored on the TV. **Forget pairing** remains available to remove the entire LG configuration, including the TLS pin, when intentionally changing devices/trust. Xiaomi and other app settings are unaffected.

A wire `401 ...` error or structured `errorCode: 401` becomes `LgAuthorizationException`, retaining numeric code and the TV reason internally. Registration, input-list, input-switch, and power-off denials invalidate the local grant, close the session, enter `AUTHORIZATION_REQUIRED`, and stop automatic reconnect. English/Hebrew UI directs the user to refresh authorization without showing raw JSON. Other failures retain existing handling. WSS and certificate validation/pinning are unchanged.

## SSAP requests and connection lifecycle

Messages are JSON objects with `type`, `id`, `uri`, and optional `payload`. The app assigns a unique ID to each request, matches replies by ID, rejects `error` and `returnValue: false`, and times out requests. One reader owns each WebSocket. The TV becomes Connected only after registration and `ssap://tv/getExternalInputList` succeed. A closed connection moves to Disconnected and retries after 5, 10, 20, 30, then 60 seconds; initial registration failures do not loop indefinitely. The ViewModel closes the transport, pending requests, discovery, and coroutine scope when it is cleared.

The source buttons map PS5 to `HDMI_1`, Mac mini to `HDMI_2`, Xiaomi to `HDMI_3`, and PC to `HDMI_4`. The controller first checks these stable IDs against the TV's returned `devices[].id` values, then sends `ssap://tv/switchInput` with `{ "inputId": "HDMI_N" }`. User-facing labels are not used for matching.

Power off sends `ssap://system/turnOff`. When the LG connection is absent, the Power button takes the wake path. Power on sends the standard 102-byte Wake-on-LAN magic packet on UDP port 9 to local broadcast destinations, using the selected device's persisted MAC addresses. The two known MACs for this installation are assigned to the selected TV by `LgInstallation`, separate from packet and SSAP code. A deployment with a different TV must replace this installation configuration. [LG's mobile power guidance](https://www.lg.com/us/support/help-library/lg-tv-how-to-set-up-the-lg-thinq-app-on-your-lg-smart-tv--20152745625356) says network power-on support depends on webOS version and TV settings. The actual wake path through this home's network is unproven.

## References and limits

Protocol and discovery behavior were checked against [LG's Connect SDK webOS TV service](https://github.com/ConnectSDK/Connect-SDK-Android-Core/blob/master/src/com/connectsdk/service/WebOSTVService.java), [its WebSocket registration client](https://github.com/ConnectSDK/Connect-SDK-Android-Core/blob/master/src/com/connectsdk/service/webos/WebOSTVServiceSocketClient.java), and [Connect SDK's external input API](https://connectsdk.com/en/latest/apis-and/and-webostvservice.html). The [LGTV Companion maintainer's firmware compatibility investigation](https://github.com/JPersson77/LGTVCompanion/issues/351) reports that placing rights in an unsigned outer manifest restores access on affected recent firmware. That report motivates this generic strategy; it does not establish that the 55UK6700YVD has that firmware or the same signed-manifest defect. [Connect SDK's permission update behavior](https://github.com/ConnectSDK/Connect-SDK-iOS-Core/blob/master/Services/WebOSTVService.m) also clears a saved key when requested rights change. The implementation here is independent; no third-party manifest/signature or source code was copied. The LG 55UK6700YVD [product support page](https://www.lg.com/levant_en/support/product/lg-55UK6700YVD.AMF) identifies the target model.

Previous Windows CLI pairing, input enumeration, and switching to HDMI 3 are physically proven. As reported on 2026-10-04, MyRemote discovers the LG, registers, and reaches Connected (which includes input-list retrieval); control requests reach the TV but switching to Mac mini / Xiaomi fails with `401 insufficient permissions`. Corrected authorization after refresh, successful MyRemote input switching, power off, and Wake-on-LAN remain unproven on the physical LG. This adapter uses secure port 3001; a different TV exposing only plaintext port 3000 would require a deliberate compatibility decision. The recorded registration on this target already proves the WSS path is usable.
